# PlatformClaw v2026.7.12

Date: 2026-07-12

## 추가

- Credentials 탭을 추가했습니다. 사용자는 Jira, GitHub, 사내 API 키처럼 Skill에서 사용할 토큰 값을 계정 범위로 등록하고 교체할 수 있습니다.
- 관리자용 Credential 유형 관리를 추가했습니다. 관리자는 등록 가능한 토큰 종류, 표시 이름, 설명, 영어 설명, 사용 스킬 안내, 교체 주기를 모달에서 관리할 수 있습니다.
- Skill 코드에서 `from platformclaw import credentials`로 런타임 Credential을 조회할 수 있는 Python SDK 경로를 추가했습니다.
- Skill 실행 전에 필요한 Credential이 없는지 확인하는 사전 점검을 추가했습니다. 필요한 값이 없으면 실행 전에 등록 안내가 표시됩니다.
- Credential 사용 이력을 남기는 감사 로그 기반을 추가했습니다.
- 직원 그룹과 멤버십 관리 화면에 보관된 항목 표시와 복원/보관 흐름을 추가했습니다.

## 변경

- Credential 값은 저장 후 다시 화면에 표시하지 않으며, 서버 암호화 키가 준비되지 않으면 저장 버튼을 비활성화하도록 변경했습니다.
- Skill이 Credential을 사용할 때 소유자는 현재 Runtime의 로그인 계정으로 고정됩니다. Skill, LLM, 스크립트 인자는 Credential 소유자를 지정할 수 없습니다.
- 그룹방 실행에서는 개인 Credential이 기본 차단되도록 정리했습니다.
- Web 채팅 실행에서 직원 계정 정보가 Runtime까지 유지되도록 변경했습니다.
- Skill 생성 안내를 workspace 기준 경로와 더 자연스럽게 맞췄습니다.
- 직원 화면의 세션 복원, 메인 세션 우선순위, 채팅 박스 여백, 패널 자막 표시를 정리했습니다.

## 수정

- VOC 모달이 열리지 않거나 제출 흐름이 끊기던 문제를 수정했습니다.
- 직원 세션 탭 복원 시 세션 목록이 최신 상태로 다시 로드되지 않던 문제를 수정했습니다.
- 세션 라벨이 클라이언트 간에 남아 보이던 문제를 수정했습니다.
- Provider 모델 호환 파라미터가 일부 모델에서 맞지 않던 문제를 수정했습니다.
- Credential 화면의 한국어/영어 표시와 삭제/폐기 확인 문구 일부가 섞이던 문제를 수정했습니다.

## 내부 메모

- Credential 저장/조회에는 안정적인 `PLATFORMCLAW_MASTER_KEY`가 필요합니다. 운영 중 키를 바꾸면 기존 Credential은 재암호화 전까지 복호화할 수 없습니다.
- Docker sandbox Credential SDK bridge는 향후 sandboxed Skill 실행을 위해 선반영되어 있습니다. 현재 기본 검증 기준은 gateway-host Skill Runtime 실행입니다.
- Gateway host exec 승인 정책은 현재 Skill SDK 사용성 확보를 위해 임시 완화 상태입니다. 외부 또는 비신뢰 Skill을 넓게 허용하기 전 trusted Skill 정책으로 좁혀야 합니다.
